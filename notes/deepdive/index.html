DeepDive：让模型学会搜索和查证

2025.09.15 · 更新于 2026.11.28 · 鲁睿 Rui Lu · — 次阅读

DeepDive 是我和合作者关于深度搜索的一项工作。我们希望模型面对复杂问题时，能自己搜索资料、阅读网页，沿着找到的线索继续查证，直到得出答案。

我们从两件事入手：先准备需要多次查证的训练题目，再训练模型一步步搜索答案。 训练过程中，还会根据搜索词的相似程度扣除奖励，鼓励模型减少重复查询。

论文：arXiv:2509.10446 · GitHub 代码 · Hugging Face 数据集

先准备需要多次查证的题目

训练题目来自知识图谱。知识图谱记录了人物、作品、奖项等信息，以及它们之间的关系。例如，一个人参与过哪部作品，这部作品又获得过什么奖，都可以连起来，成为一道问题的线索。

DeepDive 沿着这些关系选出一条路径，将部分名称、日期改写成间接描述，再生成问题。标准答案从路径末尾的已知信息中选取，例如某个人的出生年份。回答时，模型需要先判断线索说的是哪个人、哪部作品等，再查找下一条线索。选择路径时，我们会筛掉关联过多或过少的候选对象，并让模型判断下一步是否与已有线索相关。

接着筛选题目：让一个能使用搜索工具的模型对每道题尝试四次，只保留四次都没答对的问题。这一步用来挑出对该模型仍有难度的训练题目。

最终，我们从 KILT 和 AMiner 两个知识图谱构建了 3,250 道问答。其中，1,016 道用于准备监督微调数据，2,234 道用于强化学习。在监督微调部分，通过多次尝试和筛选，得到 858 条包含搜索、阅读和作答过程的示范记录。数据规模见论文第 3.1 节。

再训练模型一步步搜索答案

模型能做三件事：搜索关键词、打开搜索结果，以及直接访问网址。读完网页后，它会决定继续查什么，最后提交答案。一次回答中的搜索、阅读和作答记录，就是训练时用到的“搜索轨迹”。

训练分两步。先让模型学习前面的示范记录，掌握工具的使用方式，这一步叫监督微调。再用多轮 GRPO 进行强化学习：针对同一个问题，让模型尝试多次，比较这些尝试的得分，再据此更新模型。工具调用格式正确、最终答案通过核验，才能获得正确性奖励。

我们还希望减少重复查询。比如，模型反复用一组相近的关键词搜索，得到的可能还是同样的信息。DeepDive 会比较一次回答里各次查询的关键词：平均相似程度越高，从奖励中扣除的部分就越多。 论文把这个做法称为“查询冗余惩罚”。

计算时，先把两次查询的关键词放在一起，重复的词只算一次；再看这些词中，有多大比例同时出现在两次查询中。这个比例就是 Jaccard 相似度。我们对一次回答中的查询两两比较、取平均，再据此计算扣除的奖励。这个设计鼓励模型根据新线索调整搜索词，减少围绕同一组关键词反复尝试。

强化学习带来了多少提升

BrowseComp 是 OpenAI 推出的深度搜索评测，包含 1,266 道需要在网上查找线索的问题。我们用它比较 DeepDive-32B 在两个训练阶段的表现。

下表采用论文 arXiv v2 表 1中的结果：

模型 BrowseComp 准确率
DeepDive-32B，仅监督微调 9.5%
DeepDive-32B，加入多轮强化学习 15.3%

加入强化学习后，准确率从 9.5% 提高到 15.3%，增加了 5.8 个百分点。这组实验使用全部 1,266 道题，最多允许 128 轮交互；重复评测两次，再取平均准确率。

论文还测试了两种做法：提高每次回答可调用工具的次数上限；让模型针对同一问题独立作答多次，再从中选择一个答案。部分训练曲线、训练设置对比和多次独立作答的实验使用 BrowseComp-266 子集，也就是从完整评测集中选出的 266 道题。

论文第 4 节还介绍了由人和模型共同出题、核查答案的方法。这两类数据也用于 GLM-4.5 的后训练，也就是在已有模型的基础上继续训练，让它进一步学习搜索和答题。

代码和数据在哪里

代码和数据已公开，可以从这里查看：

  • GitHub 代码仓库：包括构建训练数据和训练模型的代码。运行训练可以从 training/README.md 开始。
  • Hugging Face 数据集：查看训练问答，以及模型搜索、阅读网页和作答的示范记录。
